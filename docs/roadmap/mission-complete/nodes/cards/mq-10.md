# mq-10 — Autonomous repair + re-spec router (RespecPacketV1)

**Phase**: full (merge-queue)
**Node ID**: `mq-10`
**Deps**: mq-2 (7-way disposition), mq-3 (subset solver) · SP-1/SP-2
**Node credit**: **0** until independent audit, full green gates, and merge

## Purpose and boundary

The merge queue's self-healing seam. When an isolated member fails, the router classifies
it and routes it EXHAUSTIVELY: an in-place-repairable deterministic-policy failure goes to
the existing writer rework; a member at a **proven fixed point** (the same audit findings
recur across an intervening generation with no magnitude reduction — detected by the
`convergenceDetector`, NOT a retry cap) emits a frozen typed **RespecPacketV1** that re-drives
spec authoring on a DIFFERENT agent; an unclassifiable / unattributed / non-repairable failure
FAILS CLOSED to `blocked_needs_attention` (never a silent drop, never an infinite re-queue).

It builds ON the merged mq-2 `member_failure` disposition and the existing triage→new-spec
seam (`createSpecOnClient` with triage provenance + `notifyDagChanged`) — it does not fork
either. A respec materializes a replacement spec (`parent_spec_id = sourceSpecId`) so the
intent survives; the stuck spec is retired as superseded (no more in-place rework).

## Production call graph

`BatchMergeCoordinator.coordinate` → `driveMultiMemberPass` → `authorizeMultiMemberEmbark` →
`settleMemberFailure` → `routeAndSettleMember` → **`AutonomousRepairRouter.routeMemberFailure`**
(`PgAutonomousRepairRouter`, wired in `batchCoordinatorBuild.ts`). `repair_in_place` →
existing `settleFailedDrive` (writer rework); `respec`/`blocked_needs_attention` →
`retireRoutedMember` (park + dequeue, no rework).

## RespecPacketV1 (frozen Zod contract)

`engine/contracts/respecPacket.ts` — `version: 1` / `schemaVersion: "respec_packet.v1"`,
`.strict()`, `policyWaiverForbidden: literal(true)`, a closed `allowedRevisions`
(`clarify_acceptance_criteria` / `split_spec` / `revise_dag_dependencies`), a
`nextAgentRoute !== priorAgentRoute` refinement, and a `sha256:` canonical content hash
(`respecPacketHash`) = `respec_routes.packet_hash`.

## Data model

`merge_repair_routes` (migration `0090`, tenant + FORCE RLS, org-scoped): every routing
decision, oldest→newest. It is BOTH the fixed-point attempt history and the respec lineage
(`respec_routes` projection). CHECK enforces respec rows carry packet/prior/next lineage and
non-respec rows do not. Cross-org read sees zero (`*.rls.integration.test`).

## Provable / callable / visible

- **Provable**: `merge.repair.routed` (every decision) + `merge.member.respec_routed` (the
  live-run-proof event: packet hash, prior→different next agent route, generation, replacements,
  and the replacement's `specMode` — a re-spec INHERITS the stuck parent's authoring mode, and
  that mode is on the wire so the choice can never be silent).
- **Callable**: `GET /orgs/:orgId/projects/:projectId/merge-queue/repair-routes[?specId=]`.
- **Visible**: the "autonomous repair · respec lineage" panel on the merge-queue dashboard.

## Fail-closed proof

`decideRepairRoute` is a switch EXHAUSTIVE over the failure taxonomy with a `never` guard;
unattributed policy, product-decision, unknown, transient, and any unrecognized class all
route to `blocked_needs_attention`. Proven by `repairRouteDecision.test.ts` +
`mq10RepairRouterWiring.test.ts` (real `coordinate()` entry point) +
`mergeRepairRoutes.rls.integration.test.ts` (production `PgAutonomousRepairRouter`).
